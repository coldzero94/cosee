# Cosee 점검 — 2026-10-14

RunCat 동작, 프로세스 측정·종료, UX·배포를 세 에이전트가 나누어 검토했다. 첫 구현은 실행 가능한 초기 버전이었으며, 아래 수정과 검증을 거쳐도 공개 배포 준비가 끝난 것은 아니다.

## RunCat처럼 움직이는가?

Apple Silicon 개발 Mac에서 실제 메뉴 막대 앱을 실행해 확인했다. 위성 공전 중심의 첫 시안에서 **코어 탐사체**로 컨셉을 발전시켰다. 접힌 날개의 부유, 관측 날개의 전진, 두 추진 리본의 고부하 비행을 각각 32프레임으로 구현했다. 실제 레이어는 28×18pt이며 CPU 입력 0%·35%·85%에서 각각 12·약 19.5·약 40.2fps와 올바른 상태를 확인했다. 최대 100%에서는 48fps로 계산한다. 상태·속도 전환의 재생 위치 오차도 검사했다.

현재 실제 시스템 CPU 스트림의 적용과 일반 속도 주입 검사도 통과했다. 결과는 `artifacts/runner-audit.json`, 재실행은 `make audit-runner`다. 검사에서 CPU값을 주입하는 것은 실제 작업으로 컴퓨터에 부하를 만드는 시험과는 다르다.

독창적인 탐사체를 새 설치 기본값으로 추가하고 원본 러너 8종, 러너 선택·좌우 반전·속도 설정, 사용자 PNG 러너, 메뉴 막대 지표, 시스템 정보 및 사용자 JSON 지표를 원본에서 유지했다. 상용 RunCat의 전체 기능·러너와 동일하다고 보장하지 않는다.

Intel의 비활성 화면에서 아이콘이 비던 원본 제약에는 정적 fallback을 추가했다. Intel 단일 화면에서는 애니메이션을 유지하고, 여러 화면에서는 정지 프레임을 표시한다. 화면 연결·제거 시 전환하며 두 아키텍처로 컴파일했지만, 실제 Intel 다중 화면 동작은 아직 검증하지 못했다.

## 가독성과 UX 개선

불투명한 배경에서 시스템 CPU·메모리 요약, 확인할 항목, 앱별 사용량, 측정 방식·시스템 상세를 구분했다. 숫자는 고정 CPU·메모리 열에서 비교하고, 모든 행에 반복되던 배경 상태와 최근 측정 문구를 펼친 상세로 이동했다. 확인할 항목에는 실제 판단 근거와 일반 종료 버튼을 함께 제공한다. 한국어·영어 및 밝은·어두운 화면의 fixture 미리보기는 `artifacts/dashboard-sections-*.png`다.

## 발견하고 수정한 문제

| 문제 | 수정 |
| --- | --- |
| 개발용 앱의 서명 때문에 실행 실패 | Debug의 dylib부터 서명하고 런타임 옵션 분리. Release의 Hardened Runtime 유지 |
| Docker 같은 메뉴 막대 앱 누락 | 독립 accessory 앱을 인식하고, 내장 helper 앱은 별도 앱으로 중복 계산하지 않음 |
| 같은 경로의 여러 앱 인스턴스에 helper를 잘못 합침 | 부모 관계를 우선하며, 경로만으로 소유 앱이 모호하면 미분류로 유지 |
| helper 생성·종료 중 지속 CPU 근거가 초기화됨 | 이미 측정된 CPU 하한이 기준 이상이면 지속 시간 유지 |
| 시스템 앱 보호 목록의 대소문자 불일치 | 식별자 정규화와 시스템 accessory 경로 보호 |
| 앱 목록이 뒤에 있고 내부 스크롤이 좁음 | 앱 우선 단일 스크롤, 검색, 더 보기, 정상·빈 결과·오류 상태 구분 |
| 메모리 기록을 저장하지만 화면에서는 미표시 | 정렬에 맞춘 CPU/메모리 차트, 완전한 측정만으로 증가 근거 계산 |
| 로그인 시 실행 실패가 보이지 않음 | 승인 필요·실패 안내, 설정 진입, 다시 활성화할 때 상태 동기화 |
| 사용자 지표의 상대 갱신 시각이 멈춤 | 측정 갱신 시 기준 시각 갱신 |

앱 일반 종료는 선택과 확인을 요구하고, 실행 신원과 보호 조건을 다시 검증한다. 실제 사용자 앱을 종료하는 시험은 수행하지 않았다. 저장 대화상자 및 종료 거부는 실사용 확인이 필요하다.

## 통합 검증

전체 Swift Testing 219개, strict lint, arm64+x86_64 앱 빌드와 실제 탐사체 실행 감사가 통과했다. 한국어·영어, 밝은·어두운 UI 미리보기를 확인했다. Release 포장에서는 불필요한 coverage 계측을 끄고, 삭제된 StoreKit 설정의 Xcode 참조도 제거했다. 새 ZIP·DMG를 생성하고 DMG에서 복사한 앱의 서명, 두 아키텍처, 실제 프로세스 읽기, 16초 실행 유지 및 Release coverage 계측 제거를 확인했다. 설치 감사 결과는 `artifacts/development/install-audit.json`이다. 이 문서의 검사 결과는 로컬 실행 결과이며 GitHub Actions의 검사 결과와 구분한다.

## 짧은 성능 측정

Release 설치본을 4초 준비한 뒤 대시보드를 닫은 상태에서 약 12초 측정했다. 자체 프로세스의 평균 CPU는 코어 1개 기준 약 2.0%였다. WindowServer의 합성 비용은 포함하지 않으며, 장시간 사용이나 대시보드가 열린 상태의 성능을 보장하는 결과는 아니다. 이전 Debug 캡처의 순간 CPU 수치를 원생 프로세스 수집기 탓으로 단정할 근거는 없었다.

## 동작 접근성

macOS의 동작 줄이기를 켜면 정지 프레임을 사용하도록 연결했다. Intel 다중 화면에서도 정지 프레임을 사용한다. 현재 실행 검사에서는 동작 줄이기가 꺼진 조건을 확인했으며, 설정을 켠 실사용 GUI 확인은 추가로 필요하다.
